# 그룹 세션 코어 — 설계

## 배경

측정 코어(2026-09-02 스펙)는 혼자 쓰는 도구였다. 방향이 바뀌었다: 여러 사람이 각자의 앱에서
온라인으로 모이고, 조는 사람이 감지되면 **다른 참가자가 그 사람을 깨워준다**.

최종 목표는 계정 기반 공개 서비스지만, 그건 하나의 스펙에 담을 크기가 아니라 셋으로 나눈다.

| # | 서브프로젝트 | 상태 |
|---|---|---|
| **1** | **실시간 세션 코어** — 방 참여, 상태 동기화, 깨우기 | **이 문서** |
| 2 | 계정과 지속 데이터 — 가입, 친구/그룹, 기록 | 나중 |
| 3 | 공개 운영 — 호스팅, 남용 방지, 약관·동의, 요금 | 나중 |

1번을 먼저 하는 이유: 이 제품에서 유일하게 불확실한 것은 "코어가 내는 신호로 남을 깨우는 게
실제로 쓸 만한가"이다. 계정은 잘 알려진 문제이고 나중에 1번을 감싸면 된다. 반대 순서로 하면
쓰지도 않을 데이터를 위해 스키마부터 짓게 된다.

1번은 계정 없이 임시 방 코드로 동작한다.

## 결정 사항 (브레인스토밍 결과)

| 질문 | 결정 | 이유 |
|---|---|---|
| 최종 범위 | 계정 기반 공개 서비스 | 사용자 결정 |
| 지금 만들 것 | 실시간 세션 코어만 | 유일하게 불확실한 부분 |
| 깨우는 방식 | **다른 사람이 버튼을 눌러** 자는 사람 기기에서 소리 | 사람이 한 번 걸러 오탐이 줄고, 그룹이라는 것 자체가 의미를 가진다 |
| 공개 입도 | **졸음 여부만** (`present` / `drowsy` / `unmeasurable`) | PERCLOS 수치는 개인 보정값이라 사람 간 비교가 원천적으로 무의미하다. 숫자를 나란히 놓으면 사람들은 반드시 비교하고 그 비교엔 근거가 없다 |
| 서버 | Node + `ws` 직접 구현 | 어려운 건 인프라가 아니라 방 상태 기계다. 생체 파생 데이터의 경로를 초기에 벤더에 넘기지 않는다 |
| 저장소 | 단일 패키지에 `shared/`, `server/` 추가 | 기존 96개 테스트가 그대로 도는 게 더 중요하다. 워크스페이스는 YAGNI |
| UI | 이번 범위 밖 | 루프를 굴려볼 최소 껍데기만 |

## 핵심 원칙 — 보낼 데이터를 애초에 만들지 않는다

PERCLOS 수치도 EAR도 영상도 서버로 보내지 않는다. 방을 넘는 것은 세 값 중 하나뿐이다.
가장 확실한 프라이버시 조치는 데이터를 만들지 않는 것이다.

측정 코어가 3라운드에 걸쳐 지킨 정직성이 여기서 무너지면 안 된다: **"모른다"를 "멀쩡함"으로
보여주지 않는다.** 자리를 비웠거나 기계가 버벅이는 상태는 `unmeasurable`이고, 그건
`present`가 아니다.

## 저장소 구조

```
perclos/
  src/       # 기존 클라이언트. 코어 7개 모듈 — 이동 없음
  shared/
    protocol.ts   # 메시지 타입. 클라이언트와 서버가 함께 import
    room.ts       # 방 상태 기계 (순수)
  server/
    index.ts      # ws 서버. room.ts를 소켓에 연결하는 얇은 껍데기
```

`tsconfig.json`의 `include`에 `shared`와 `server`를 더한다. 서버는 `tsx`로 실행한다.

## 프로토콜

```ts
type Status = 'present' | 'drowsy' | 'unmeasurable';
```

| 방향 | 메시지 | 내용 |
|---|---|---|
| C→S | `join` | 방 코드, 표시 이름 |
| C→S | `state` | `Status`. 주기적으로 보내며 하트비트를 겸한다 |
| C→S | `wake` | 깨울 대상 참가자 id |
| S→C | `joined` | 내 id와 현재 참가자 목록 |
| S→C | `participants` | 변경이 있을 때만 브로드캐스트 |
| S→C | `wakeRequest` | 누가 나를 깨웠는지. 대상자만 받는다 |
| S→C | `error` | 거부 사유 코드 |

**시각은 전부 서버 시계로 찍는다.** 코어의 `AlertEvent.at`은 `performance.now()` 기반이라
기계마다 원점이 달라 비교가 불가능하다. 그 값은 클라이언트 안에서만 쓰고 방을 넘기지 않는다.

## 상태 판정

### 코어 이벤트 → `drowsy`

코어는 순간 이벤트(`perclos` / `microsleep` / `saturated`)를 내는데 방에 필요한 것은 지속 상태다.

- 세 이벤트 중 무엇이든 오면 → `drowsy`
- 해제 조건: 코어가 재무장되거나(PERCLOS 8% 아래), **90초** 동안 경고가 한 번도 없으면 → `present`

`saturated`는 자는 동안 60초마다 반복되므로 `drowsy`가 유지된다.

### `unmeasurable`에 들어가는 것

전부 "모른다"이지 "멀쩡함"이 아니다.

- `analyzeWindow().value === null` (유효 프레임 50% 미만 — 자리 비움, 얼굴 미검출)
- 저커버리지 (`observedMs`가 낮음 — 기계가 버벅여 초당 4프레임 미만)
- 카메라 실패, 보정 미완료, 재보정 필요

### 나간 사람과 고개를 떨군 사람

자다가 고개를 완전히 떨구면 얼굴이 사라져 `unmeasurable`이 되는데, 자리를 비운 것과 신호가
똑같다. 코어는 이 둘을 구분할 수 없다.

**직전 상태로 가른다.** 서버가 참가자의 직전 상태를 기억한다.

| 전이 | 해석 | 깨우기 대상 |
|---|---|---|
| `drowsy` → `unmeasurable` | 졸다가 사라짐. 고개를 떨궜을 가능성 | 유지 |
| `present` → `unmeasurable` | 자리 비움 | 아님 |

### 연결 끊김

상태가 아니라 별개 축이다.

- 15초 무소식 → `disconnected` 표시
- 30초 무소식 → 목록에서 제거
- `disconnected`인 사람은 깨우기 대상이 아니다. 전달이 안 되기 때문이다

## 깨우기 남용 방지 — 서버가 강제한다

"남을 깨울 권한"은 곧 "남을 방해할 권한"이다. UI 매너가 아니라 프로토콜 수준에서 막는다.
클라이언트를 믿지 않는다.

- `drowsy`이거나 졸다가 사라진 사람만 깨울 수 있다. 멀쩡한 사람은 깨울 수 없다
- 같은 대상을 향한 깨우기에 **30초** 쿨다운
- 자기 자신은 깨울 수 없다
- 위 조건을 어긴 요청은 `error`로 거부한다

## 방

- 6자 영숫자 코드
- 서버 메모리에만 존재한다. 저장하지 않는다
- 마지막 참가자가 나가면 사라진다

## 아키텍처 — 순수 층과 I/O 층

`shared/room.ts`는 소켓도 타이머도 모른다.

```
(현재 방 상태, 들어온 메시지, 지금 시각) → (새 방 상태, 내보낼 메시지들)
```

`server/index.ts`는 이것을 소켓에 연결하는 얇은 껍데기다. 소켓에서 메시지를 꺼내 `room.ts`에
넘기고, 돌려받은 메시지를 소켓으로 내보낸다. 만료 검사는 서버가 1초마다 지금 시각과 함께
`room.ts`를 호출해 처리한다.

측정 코어에서 이 패턴이 실제로 값어치를 했다. 전체 리뷰가 잡은 치명적 결함이 전부 순수 로직
쪽이었고, 카메라 없이 돌릴 수 있었기 때문에 잡혔다.

## 테스트 전략

`shared/room.ts`를 네트워크 없이 전부 덮는다.

- 참여와 이탈, 방 생성과 소멸
- 코어 이벤트 → `drowsy` 전환과 90초 해제
- `drowsy → unmeasurable`과 `present → unmeasurable`의 구분
- 깨우기 권한: 멀쩡한 사람 거부, 자기 자신 거부, 30초 쿨다운
- 하트비트 만료: 15초 `disconnected`, 30초 제거
- 브로드캐스트가 실제로 변경이 있을 때만 나가는지

`server/index.ts`는 순수 층 위의 얇은 껍데기라 단위 테스트 대상이 아니다. 타입 검사와
수동 확인으로 검증한다.

## 이번 범위 밖

- 계정·로그인 (서브프로젝트 2)
- 지속 저장, DB (서브프로젝트 2)
- 화면 설계 (별도)
- 배포·호스팅·요금 (서브프로젝트 3)
- 서버 다중 인스턴스, 수평 확장

클라이언트는 루프를 굴려볼 최소 껍데기만 만든다: 방 코드 입력, 참가자 목록 텍스트,
깨우기 버튼, 깨우기를 받으면 소리.

## 한계 (문서와 UI에 명시할 것)

- 졸음 판정은 측정 코어의 정확도를 그대로 물려받는다. 코어의 한계(운전 연구 기준 임계값,
  안경 반사, 저조도)가 그대로 남는다
- 자리 비움과 고개 떨굼의 구분은 직전 상태에 기댄 **추정**이지 관측이 아니다
- 의료기기가 아니다
