# PERCLOS 측정 코어 — 설계

## 배경

노트북 내장 웹캠으로 졸음(각성도 저하)을 실시간 감지해 경고하는 프로그램. Wavely와는 **별개 프로젝트**다.
Wavely에 넣지 않은 이유는 카메라 상시 접근이라는 성격이 Wavely의 "기록하는 앱"이라는 정체성과 맞지 않고,
기술 검증이 먼저 필요하기 때문이다. 코어를 순수 함수로 분리해 두면 나중에 Wavely로 옮기는 선택지는 남는다.

이 문서는 **측정 코어**만 다룬다. 프론트엔드(화면, 경고 연출, 설정 UI) 설계는 코어 검증 후 별도로 한다.

## 결정 사항 (브레인스토밍 결과)

| 질문 | 결정 | 이유 |
|---|---|---|
| Wavely 안 / 밖 | 별개 프로젝트 | 성격이 다르고 기술 검증이 선행돼야 한다 |
| 핵심 쓰임새 | **실시간 졸음 경고** | 기록·분석은 나중. 지금은 "뜨면 알려준다"가 전부 |
| 스택 | Vite + TypeScript + MediaPipe Tasks Vision (WASM) | 가장 빨리 검증 가능. Tauri로 감쌀 때 코어는 그대로 이식된다 |
| 서버 | 없음 | 모델이 WASM으로 로컬 실행된다. 오프라인 동작 |
| 임계값 방식 | **개인 보정 필수** | 고정 EAR 임계값은 눈 크기·안경·조명에 따라 빗나간다 |
| 감김 판정 | P80 정의에서 유도 | 임의의 숫자를 쓰지 않는다 |
| 첫 단계 범위 | 코어 + 숫자 확인용 최소 표시 | 저장·차트·설정 화면은 넣지 않는다 (YAGNI) |

## 핵심 원칙 — 그럴듯한 숫자를 만들지 않는다

보정이 안 됐거나, 얼굴이 안 잡히거나, 창 안의 유효 프레임이 모자라면 **수치를 내놓지 않는다**(`–`).
자리를 비운 것을 졸음으로 오판하는 것이 이 부류 프로그램에서 가장 흔한 버그다.

## 아키텍처

I/O 층과 순수 계산 층을 분리한다. 순수 층은 카메라 없이 전부 테스트한다.

| 모듈 | 역할 | 테스트 |
|---|---|---|
| `src/camera.ts` | `getUserMedia`, 640x480@30fps 요청, 권한 거부·장치 없음 처리 | I/O ❌ |
| `src/faceTracker.ts` | MediaPipe FaceLandmarker 초기화, `detectForVideo()`, 모델 로컬 번들 | I/O ❌ |
| `src/ear.ts` | landmark 배열 → 좌/우 EAR와 평균 | 순수 ✅ |
| `src/calibration.ts` | 기준선 수집·검증, 감김 임계값 산출, 드리프트 갱신 | 순수 ✅ |
| `src/perclos.ts` | `{시각, 상태}` 시퀀스 → 슬라이딩 PERCLOS, 깜빡임, 미세수면 | 순수 ✅ |
| `src/alertPolicy.ts` | 지표 → 경고 이벤트. 히스테리시스·쿨다운 | 순수 ✅ |
| `src/app.ts` | 위를 엮는 루프 (`requestVideoFrameCallback`) | ❌ |

### 데이터 흐름

```
video frame → landmarks → EAR ─┬→ (임계값 비교) → 상태 → 60초 링버퍼 → PERCLOS%
                               └→ calibration (기준선 드리프트 갱신)          ↓
                                                                    alertPolicy → 경고 이벤트
```

`requestAnimationFrame`이 아니라 `requestVideoFrameCallback`을 쓴다. 실제 비디오 프레임에 동기화되어
프레임 누락과 타임스탬프가 정확하다.

## EAR (Eye Aspect Ratio)

눈 landmark 6점의 세로 거리 합을 가로 거리로 나눈 비율. 비율이므로 카메라와의 거리, 얼굴 크기에 강건하다.

```
EAR = (|p2-p6| + |p3-p5|) / (2 * |p1-p4|)
```

좌우 눈을 각각 계산해 평균한다. 한쪽 눈만 가려지는 경우(측면 각도)를 위해 좌우 차이가 크면 결측 처리한다.

## 보정

### 최초 보정 (약 20초)

1. **열린 눈 15초** — "평소대로 화면 보세요". EAR 샘플의 **P75**를 `openEAR`로 쓴다.
   중앙값이 아니라 P75인 이유: 이 구간에 깜빡임이 섞여 값이 아래로 튄다.
2. **감은 눈 3초** — "눈 감아주세요". 중앙값을 `closedEAR`로 쓴다.
3. **유효성 검사** — `openEAR - closedEAR < 0.08`이면 조명이나 각도가 나쁜 것이다.
   그럴듯한 값을 쓰지 말고 **재보정을 요구한다**.

### 감김 임계값 — P80 정의에서 유도

PERCLOS의 표준 정의는 "동공이 80% 이상 덮인 시간의 비율"이다. 눈꺼풀 닫힘 비율을 EAR에 선형 매핑하면:

```
closedThreshold = closedEAR + 0.2 * (openEAR - closedEAR)
```

이 값 이하인 프레임을 감김으로 센다. 임의로 고른 숫자가 아니라 정의에서 나온 값이다.

### 드리프트 갱신

자세를 고쳐 앉거나 해가 지면 기준선이 이동한다. **열림으로 판정된 프레임만** 모아 5분 롤링 P75로
`openEAR`을 EMA(alpha = 0.02, 1초마다 갱신)로 천천히 갱신한다. `closedEAR`은 고정한다 — 감은 눈의 EAR은 거의 변하지 않는다.

## 결측 처리

다음 프레임은 **결측**으로 기록하고 감김/열림 어느 쪽으로도 세지 않는다.

- 얼굴 미검출 (자리 비움)
- 검출 결과가 비었거나 얼굴 경계가 프레임을 벗어남 (안경 반사, 저조도, 극단적 측면 각도)
- 좌우 눈 EAR 차이가 `0.3 * (openEAR - closedEAR)`를 초과함 (한쪽 눈만 가려진 상태)

60초 창에서 유효 프레임이 **50% 미만**이면 PERCLOS를 계산하지 않고 `–`로 표시하며, 경고도 하지 않는다.

## 경고 판정

| 조건 | 동작 |
|---|---|
| PERCLOS (60초 슬라이딩, 1초 갱신) >= **15%** | 경고 |
| 연속 감김 >= **500ms** (미세수면) | 즉시 경고, PERCLOS와 무관 |
| 경고 발생 후 **60초** | 쿨다운. 재경고 없음 |
| 재무장 | PERCLOS가 **8%** 아래로 내려가야 다시 경고 가능 |

히스테리시스를 두는 이유는 임계 근처에서 경고가 연타되는 것을 막기 위해서다.

`alertPolicy`는 `{ type: 'perclos' | 'microsleep', value, at }` 이벤트만 반환한다.
소리·알림 방식은 프론트엔드 설계에서 정한다. 코어는 연출을 모른다.

보조 지표(평균 깜빡임 지속시간, 분당 깜빡임 수)는 계산하되 **경고 판정에는 쓰지 않는다**.
개인차가 너무 커서 임계값을 신뢰할 수 없다.

## 프라이버시

- 영상 프레임은 메모리에서만 처리한다. 저장하지 않고 전송하지 않는다.
- 네트워크 호출이 없다. 모델은 번들된 로컬 파일에서 로드한다.
- 디스크에 남는 것은 보정 수치뿐이다.

## 테스트 전략

합성 EAR 시퀀스 픽스처로 순수 층 전체를 검증한다. 카메라 없이 전부 돌아간다.

- **PERCLOS 정확도** — 30fps x 60초 = 1800 프레임에 감김 구간을 심고 기대 비율과 대조
- **미세수면 경계** — 499ms는 미검출, 501ms는 검출
- **쿨다운** — 경고 직후 60초 내 재경고 없음, 재무장 조건 확인
- **보정 거부** — `openEAR - closedEAR`가 0.08 미만이면 보정 실패를 반환
- **결측 처리** — 유효 프레임 50% 미만인 창은 값 대신 결측을 반환
- **P80 임계값** — 알려진 open/closed 쌍에 대해 유도식대로 계산되는지

## 한계 (문서와 UI에 명시할 것)

- 15% 임계값은 운전 시뮬레이터 연구에서 나온 값이다. 책상 작업에 그대로 맞지 않을 수 있으므로
  개인이 조정 가능하게 둔다.
- 의료기기가 아니다. 수면장애 진단이나 운전 적합성 판정에 쓸 수 없다.
- 안경 반사와 저조도에서 정확도가 떨어진다. 이것을 숨기지 않고 결측으로 드러낸다.
