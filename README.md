# PERCLOS

웹캠으로 PERCLOS(눈꺼풀이 동공을 80% 이상 덮은 시간의 비율)를 계산해 졸음을 감지하고,
같은 방의 다른 참가자가 조는 사람을 깨울 수 있게 하는 도구.

## 설치

```bash
npm install
```

```bash
npm run assets
```

```bash
curl -L -o public/models/face_landmarker.task https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task
```

## 실행

터미널 두 개가 필요하다.

```bash
npm run server
```

```bash
npm run dev
```

`http://localhost:5173`을 연다. 이름과 방 코드(영숫자 6자)를 넣고 시작을 누른다.
같은 방 코드를 쓰면 같은 방에 모인다. 약 20초 보정을 거친 뒤 서로의 상태가 보이고,
조는 사람 옆에 깨우기 버튼이 생긴다.

보정은 15초 동안 평소대로 화면을 보고, 3초 동안 눈을 감는 순서다. 고정 임계값은
사람마다 빗나가기 때문에 이 과정을 건너뛸 수 없다.

## 다른 기기에서 접속하기 (https)

`getUserMedia`는 보안 컨텍스트에서만 동작한다. localhost는 예외지만 LAN IP로 접속하면
https가 아닌 한 브라우저가 카메라 요청을 **조용히 차단한다.** 권한 창도 뜨지 않는다.

인증서를 한 번 만들면 `npm run dev`와 `npm run server`가 자동으로 https/wss로 뜬다.

```bash
npm run cert
```

인증서에는 이 기기의 LAN IP가 들어간다. IP가 바뀌면 `certs/`를 지우고 다시 만든다.

접속하는 기기에서 **두 주소 모두** 인증서 경고를 통과시켜야 한다.

1. `https://<IP>:8787` — 먼저 연다. 경고를 통과시킨 뒤 페이지 내용은 무시해도 된다
2. `https://<IP>:5173` — 앱

8787을 먼저 통과시키지 않으면 앱은 열리지만 **서버 연결만 조용히 실패한다.**
브라우저는 WebSocket의 인증서 거부를 사용자에게 묻지 않기 때문이다.
그 경우 앱이 "서버: 끊김"과 함께 이 안내를 띄운다.

다시 http로 돌아가려면 `certs/` 디렉터리를 지우면 된다.

## 무엇이 오가는가

방을 넘는 것은 이름과 세 가지 상태(`present` / `drowsy` / `unmeasurable`)뿐이다.
영상도, EAR도, PERCLOS 수치도 서버로 보내지 않는다. 방은 서버 메모리에만 있고
마지막 참가자가 나가면 사라진다.

수치를 공유하지 않는 이유는 프라이버시만이 아니다. PERCLOS는 개인 보정값이라
사람 간 비교가 원천적으로 무의미하다. 내 12%와 다른 사람의 12%는 다른 뜻이다.

## 한계

- 졸음 판정은 측정 코어의 정확도를 그대로 물려받는다 (운전 시뮬레이터 연구에서 나온
  임계값, 안경 반사, 저조도)
- 자리 비움과 고개 떨굼의 구분은 직전 상태에 기댄 추정이지 관측이 아니다
- 기계가 버벅여 초당 4프레임 아래로 떨어지면 시간 기반 검출이 꺼진다. 그때는 `present`가
  아니라 `측정 불가`로 보고한다
- 재보정이 필요해지면 이 최소 하네스에는 복구 경로가 없다. 새로고침 후 다시 시작해야 한다
- **의료기기가 아니다.** 수면장애 진단이나 운전 적합성 판정에 쓸 수 없다
